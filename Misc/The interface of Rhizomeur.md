
# The Interface

The Interface is not just a paintjob we apply an top of all of the things we have already coded; on the contrary, it is thing that allows us to interact with the tool. Knowing this, it is of a primordial importance that the Interface does not hold back the features, but instead that hit expands them. The Interface is the thing which will allow for all of the Engines to work in unison. In order for the engines to be able to work together, the interface needs to allow them to communicate coordinate to highlight what's important at any given moment. 

## Visual direction and inspiration 

In the same way Nick Milo says that color is a way of sparking creativity, I think that space is too. That's why I am very inspired by the visuals of [Lifestreams](https://youtu.be/Ioki1q6yCok?si=sRFsdT4lWJRrWCVo): they excite the mind with the third dimension.

## Not just an interface, a tool

### How I want Rhizomeur's interface to feel
I don't want interacting with Rhizomeur to feel flat or two dimensional. I want it to feel like interacting with a real tool. What I mean by this is that I don't just want the Interface to feel like some structure which describes how the tool can be used. I want it to feel like every part of Rhizomeur is real and alive and that they are interacting with each other. Each Engine is a part of the body.

### The danger of the new and the potential of the experimental 

These are some very pretty words, but it can definitely be said that this effort can have the potential to harm. By trying to make my system more *experimental* and *new*, I might prevent it from even being *useful* or *good*. There is probably a reason that so many interfaces are simply flat windows with different panels and popups; it might simply be the most efficient way of interacting with computers as we know them. Even still, I can't help but be drawn to the novelty and futuristic like qualities of system like Lifestreams. I can't help but think that, by simply taking a step into the experimental, I could make a truly unique and beautiful user experience. Sometimes, in order to innovate, we have to brake rules. But if you brake too many rules, you might just make complete shit. Or you might make something that only a small amount of people like. There's nothing wrong with that. Considering that this tool is already something that very few people would find useful or even interesting means that I can allow myself to take more risks in creating something innovative. 

## How the interface will work 

I want the interface to be very, very modular, so that users feel the way in which the different parts interact with each other, and so that they can have many options in customization. 

The interface is the body which hold everything else together.
