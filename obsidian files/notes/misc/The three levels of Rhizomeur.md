
# The Three Pillars of Rhizomeur

IN [[What is Rhizomeur#What are the makings of a perfect personal knowledge management system?]], I explained that there are five main tasks which Rhizomeur needs to be able to fulfil. I have dubbed these tasks the **Five Pillars of Rhizomeur**:
1. ***Creating*** 
2. ***Displaying*** 
3. ***Connecting***
4. ***Organizing***
5. ***Contextualizing*** 

I think these five pillars are important to think of on the philosophical level of *what this system needs to be able to do*; however, on a more technological level, It's better to think of Rhizomeur as having three levels. I will call these levels the **Three Levels of Rhizomeur**:
1. ***Notes*** - This level is where the notes are described. As I have mentioned elsewhere, notes are KUs which represent notes which describe things. In order to create this level, notes have to exist, and they have to have connexions to each other. These connexions will be described by a new language which I will create which will allow for queries involving semantic bidirectional links. 
2. ***Graphs*** - Once we have created notes, we will need to start organizing these such notes. In order to do this, we will need to create graphs. Graph will need to be recursive, meaning that, not only can we organize notes, but we can also organize organization itself! 
3. ***Interface*** - The interface is what allows us to carry out all of the actions described by the Five Pillars of Rhizomeur (which is what I explain below). I would note here that *organizing* is somewhat of a science which I have described in my theories, but *contextualizing* is left more to interpretation. There are many ways to contextualize.
