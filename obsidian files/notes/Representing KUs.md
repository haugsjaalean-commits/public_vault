
## Representing KUs



This KS is based on the creation of notes. Each of these notes represents a KU. The question is how to represent these KUs. I could say that there are two main design philosophies when it comes to defining the KUs using notes (`.md` files). Both methods assume that KCs are being represented by a table in a database; however, the difference is in how CCs are represented. The first approach assumes that CCs are simply defined by the contents of the note, and the second approach takes a wider view of the situation and bases the CCs on the greater concept of the note. 

### CCs defined by note contents 

In this method, The CCs of the KUs which are represented by the `.md` notes are described by the contents of these notes. This means that we are considering the text contained inside of the files and inside of the links to be *meaning* itself. When we think about things in this way, we realize that the vast majority of notes created will need to be specified as being notes, otherwise, marking a note as needing to be better linked doesn't make sense: a *dog* cannot be poorly linked, but a note about a dog can be. Given this, we would have base notes which describe basic things like *dog* or *cat*, and we would also have note notes like *dog note* and *cat note*:

This idea seems fine at first until we notice some logical holes in the system. It would seem that, in a system about making connexions between things and concepts, one would want the things and concepts to be connected. If a dog is defined by its connexions to other things, then in the system where I claim to be defining dog, it should definitely be connected to related concepts which help us understand what *dog* even is. This, however, would not make sense in the system I just described, as, if we start writing things about something, we want to consider it as a note. This means that, by following this logical sequence, we arrive at this conclusion: if we create a file where we write about something, it's necessarily a note. This brings us to our second and--according to me--more correct solution. 






### CCs defined by concept


I think that it's far better to think of the CCs of notes as being defined in a more theoretical way, which takes into account the context of the whole system. Instead of thinking of CCs as being defined by the notes and connexions and text, I would wager that it's better to think of them as being defined by the greater context. 

In the above method, we said that the notes were the things that defined the KU. In this method, it's the other way around: we have notes and connexions, and, looking at these, we create our purely theoretical CCs. When we do this, we see that it is impossible for a markdown file written by a person in this KS can be nothing but a note. 

CCs are note made by things; instead, we look at things and we give them CCs. When we think about things in this way, it becomes clear why this method of *CCs defined by concept* makes perfect sense.
